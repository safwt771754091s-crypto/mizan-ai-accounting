# ركاز | RAKAZ AI — منصة الذكاء المحاسبي والمالي

منصة ويب عربية (RTL) تساعد المحاسبين القانونيين وأصحاب الشركات على رفع ملفاتهم المحاسبية،
واستيرادها في قاعدة بيانات منظمة، ثم إنتاج ميزان مراجعة وقوائم مالية وتحليل مالي وكشف أخطاء
وتكرار ومخاطر — مع مساعد محاسبي ذكي لا يخترع الأرقام.

> التقرير والتحليل **مساعد** ولا يُعد رأياً قانونياً أو تقرير مراجعة معتمداً.

## التقنيات

- **Next.js 16.4.6** (App Router، Server Actions، Proxy/Middleware) + **React 19.3.1**
- **TypeScript 5.9** + **Tailwind CSS 4.3** + مكونات Radix UI بأسلوب shadcn/ui
- **Decimal.js 10.6** لكل الحسابات المالية (لا floating point)
- **Zod 4** للتحقق من المدخلات، **Recharts 3** للرسوم
- **ExcelJS** (قراءة/تصدير XLSX)، **PapaParse** (CSV)، **pdf-parse** (PDF نصي)
- **Supabase** (Postgres + Auth + Storage) مع RLS
- **Vitest 5** للاختبارات، **Playwright 1.65** للـ E2E

## التشغيل السريع (وضع Demo)

المتطلبات: Node.js 20+ (مُختبر على 24) و npm.

```bash
npm install
npm run dev
```

افتح <http://localhost:3000> وسجّل الدخول بأحد الحسابات التجريبية:

| الحساب | كلمة المرور | الدور |
| --- | --- | --- |
| `demo@rakaz.ai` | `Demo1234!` | مالك 3 شركات |
| `auditor@rakaz.ai` | `Demo1234!` | مراجع (شركة النخيل) |
| `viewer@rakaz.ai` | `Demo1234!` | مشاهد (قراءة فقط) |
| `admin@rakaz.ai` | `Admin1234!` | مدير منصة |

بيانات الشركات التجريبية: شركة النخيل للتجارة، مؤسسة الأفق للمقاولات، متجر ركاز — جميعها
بقيود متوازنة وقوائم مالية متسقة.

### إعادة ضبط البيانات التجريبية

- من الواجهة: **الإعدادات ← إعادة ضبط البيانات التجريبية**، أو
- من الطرفية: `rm -rf .rakaz-data && npm run dev`، أو
- `npm run db:seed` (يعيد بناء ملف البيانات التجريبية).

### الوضع التجريبي على منصات الاستضافة (Vercel وغيرها)

مجلد المشروع على Vercel للقراءة فقط، لذلك يتغيّر مسار ملف البيانات التجريبية تلقائياً:

| البيئة | المسار |
| --- | --- |
| محلي | `.rakaz-data/demo-store.json` في مجلد المشروع |
| Vercel / Lambda / Netlify | `$TMPDIR/rakaz-data/demo-store.json` |
| تحديد يدوي | `RAKAZ_DATA_DIR` |

إن تعذّر الحفظ على القرص (نظام ملفات للقراءة فقط) تستمر المنصة بالعمل من الذاكرة وتطبع
تحذيراً في سجل الخادم بدل إسقاط الصفحات بخطأ 500. البيانات في هذه الحالة مؤقتة:
تنتهي بانتهاء نسخة الخادم ولا تُشارك بين النسخ. **لبيانات دائمة في الإنتاج استخدم
Supabase** (`RAKAZ_DATA_MODE=supabase` مع متغيرات Supabase وملفات الترحيل).

## الإعداد الكامل مع Supabase

1. أنشئ مشروعاً على <https://supabase.com>.
2. نفّذ ملفات الترحيل بالترتيب في SQL Editor:
   `0001_core.sql` ثم `0002_ledger.sql` ثم `0003_security.sql` ثم `0004_rbac.sql` ثم
  `0005_internal_controls.sql` ثم `0006_proposals.sql` ثم `0007_rls_permissions.sql`.
  بعد الترحيل يمكن تشغيل اختبار العزل على القاعدة الحقيقية: `supabase/tests/rls_permissions.sql`.
3. انسخ `.env.example` إلى `.env.local` واملأ:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
# اختياري للسكربتات الإدارية فقط — لا يُستخدم في المتصفح
SUPABASE_SERVICE_ROLE_KEY=<service role key>

RAKAZ_DATA_MODE=supabase
```

4. أنشئ مستخدماً من صفحة `/register` (أو من Supabase Auth)، ثم أضف صفاً في
   `company_members` لربطه بشركة — أو أنشئ شركة من الواجهة ليصبح المستخدم مالكها.
5. أعد تشغيل الخادم.

> ملفات `.env.local` مستثناة من Git. لا تضع أي مفتاح في `.env.example` أو في الكود.
> للتوافق مع الإصدارات السابقة، ما زالت المتغيرات القديمة `MIZAN_*` مقبولة كقيمة احتياطية
> إن لم تُضبط متغيرات `RAKAZ_*`.

## المساعد الذكي (اختياري)

بدون مفاتيح يعمل المساعد بمنطق محلي حتمي يقرأ نتائج المحرك المحاسبي ويجيب بالعربية
(صافي الربح، أكبر المصروفات، القيود المكررة، نسب السيولة...). لعرض الجانب اللغوي عبر LLM:

```bash
AI_PROVIDER_API_KEY=<key>
AI_PROVIDER_BASE_URL=https://api.openai.com/v1   # أي مزود متوافق مع Chat Completions
AI_MODEL=gpt-4.1-mini
```

في كل الحالات تُبنى الأرقام من محرك الحسابات وتُمرَّر إلى النموذج كسياق منظم؛ النموذج
**لا يحسب ولا يخترع** القيم المالية، وأي فشل في الاتصال يعود تلقائياً للإجابة المحلية.

قبل العرض يُفحص كل رقم في إجابة النموذج مقابل القيم المحسوبة؛ أي مبلغ أو نسبة غير موجودة
يُرفض ويُستبدل بالإجابة المحلية، ويظهر سبب ذلك للمستخدم. للتحقق من اتصال المزود:

```bash
npm run ai:check
```

المزودون المدعومون، وخطوات Vercel، وسلوك الفشل: [docs/ai.md](docs/ai.md).

## الأمن باختصار

- عزل صارم بين الشركات: كل استعلام يمر بسياق الشركة والصلاحية، وRLS على مستوى الصف.
- نظام صلاحيات مؤسسي (RBAC): كتالوج مركزي للصلاحيات، ستة أدوار نظامية (منها «محاسب أول»)،
  أدوار مخصصة داخل كل شركة، وتحقق على الخادم في الصفحات وواجهات API وServer Actions —
  إخفاء الأزرار لا يُعد تحققاً.
- استيراد الملفات: تحقق من الامتداد + التوقيع الفعلي (magic bytes) + الحجم (15MB) +
  بصمة SHA-256 لمنع الاستيراد المكرر.
- جلسات Demo موقّعة بـ HMAC-SHA256.
- رؤوس أمان (X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy).
- لا أسرار في Git؛ `.env.local` فقط.

التفاصيل في [docs/security.md](docs/security.md).

## القيود المعروفة

- ملفات PDF الممسوحة ضوئياً تحتاج OCR (غير مدمج) — يُقرأ النص المضمّن فقط.
- صيغة XLS الثنائية القديمة تحتاج تحويلاً إلى XLSX.
- قائمة التدفقات النقدية تُبنى بطريقة غير مباشرة من حركة النقدية والبنك، وتظهر "غير متاحة"
  عند نقص البيانات.
- وضع Demo يخزّن البيانات في ملف JSON محلي (أو في `$TMPDIR` على منصات الاستضافة)،
  وهو للتجربة والعرض وليس للإنتاج: البيانات مؤقتة ولا تُشارك بين نسخ الخادم.
