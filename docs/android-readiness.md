# جاهزية Android — تقييم الخيارات

هذه الوثيقة **تقييم معماري فقط**. لم يُنشأ مشروع Android ولا APK في هذه المرحلة.

## 1. واقع البنية الحالية

- Next.js 16 (App Router) مع Server Components وServer Actions وRoute Handlers.
- المصادقة عبر Supabase Auth بكوكيز على الخادم (`@supabase/ssr`)، والتحقق في `src/proxy.ts`.
- البيانات تُقرأ وتُكتب على الخادم فقط، مع RLS وفصل شركات صارم.
- النشر على Vercel (Serverless + Edge Middleware).

معنى ذلك: أي غلاف أصلي **لا يستطيع** أن يعمل بلا خادم؛ التطبيق كله يعتمد على SSR وServer Actions.

## 2. الخيارات

### A. PWA فقط (المنفّذ الآن)

- التثبيت من Chrome على Android، تجربة standalone، تحديث تلقائي، صفحة عدم اتصال.
- ✅ صفر صيانة إضافية، نفس الكود، نفس النشر.
- ❌ لا وجود في Google Play، ولا وصول لميزات أصلية (إشعارات غنية، مشاركة، بصمة).
- **مناسب الآن.** هذه هي المرحلة الحالية.

### B. TWA — Trusted Web Activity (Bubblewrap)

تطبيق Android رقيق يعرض الموقع المنشور في Chrome Custom Tab موثوق (بلا شريط عنوان).

- ✅ نفس PWA بلا كود مكرر، نشر في Google Play ممكن، تحديث فوري مع كل نشر ويب.
- ✅ لا حاجة لإعادة بناء المصادقة: الكوكيز تعمل كما في المتصفح.
- ❌ يحتاج: حساب Play Console، مفتاح توقيع، ملف `assetlinks.json` على الدومين، أيقونات Play،
  سياسة خصوصية، ومراجعة Google.
- **التوصية الأولى للوصول إلى Play** بعد استقرار PWA.

### C. Capacitor مع تحميل الموقع المنشور

WebView أصلي يحمّل `https://mizan-ai-accounting.vercel.app`.

- ✅ يفتح الباب لإضافات أصلية (إشعارات، ماسح باركود، مشاركة ملفات).
- ❌ مشاكل معروفة: الكوكيز داخل WebView، `SameSite`، إعادة التوجيه بعد تسجيل الدخول،
  روابط OAuth، وسلوك `beforeinstallprompt` (غير موجود داخل WebView).
- ❌ يتطلب ضبط `site_url` و`redirect URLs` في Supabase لإضافة مخطط التطبيق (`rakaz://`).
- **مقبول لاحقاً** إذا احتجنا ميزات أصلية، لكنه أثقل من TWA بلا فائدة ملموسة الآن.

### D. Native Android (Kotlin/Compose)

- ❌ يعني إعادة بناء المنطق المحاسبي والواجهة أو بناء API عام كامل + SDK.
- **غير مبرر** قبل إثبات الطلب في السوق.

## 3. التوصية

1. **الآن:** PWA (منفّذ).
2. **بعد استقرار PWA وطلب المستخدمين:** TWA عبر Bubblewrap للنشر في Play — أقل تكلفة وأقل مخاطر.
3. **فقط عند الحاجة لميزات أصلية:** Capacitor مع تحميل الموقع المنشور، مع ضبط المصادقة والروابط.
4. **Native كامل:** لا، إلا بقرار منتج جديد.

## 4. متطلبات تقنية لأي غلاف أصلي

| المتطلب | الحالة الآن |
| --- | --- |
| HTTPS ودومين ثابت | ✅ Vercel |
| Manifest + أيقونات 512 | ✅ |
| `site_url` و`redirect URLs` في Supabase | ✅ مضبوطة على دومين الإنتاج |
| `/.well-known/assetlinks.json` (TWA) | ❌ غير موجود — يُضاف عند تنفيذ TWA |
| Deep links (`rakaz://`) | ❌ يحتاج تسجيل مخطط + تحديث `redirect URLs` |
| سياسة خصوصية منشورة | ❌ مطلوبة لمتجر Play |
| اختبار مصادقة داخل WebView | ❌ لم يُجرَ |

## 5. ما لم يُنفذ في هذه المرحلة (مقصود)

- لا مشروع Android، لا APK، لا AAB، لا توقيع.
- لا Bubblewrap ولا Capacitor في التبعيات.
- لا `assetlinks.json`.
- لا إشعارات Push.
