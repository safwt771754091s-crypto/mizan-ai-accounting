# قواعد المحاسبة والحسابات — RAKAZ AI

كل المبالغ تُعالج كـ `Decimal` (Decimal.js) وتُخزَّن كنصوص عشرية. لا تُستخدم أرقام
JavaScript العائمة في أي حساب مالي.

## 1. دليل الحسابات

لكل حساب:

- `code` (فريد داخل الشركة)، `name`، `type`، `subtype`، `parentCode`، `normalSide`.

الأنواع الخمسة وطبيعتها:

| النوع | الطبيعة الطبيعية | يزيد بالمدين؟ |
| --- | --- | --- |
| `asset` | مدين | نعم |
| `liability` | دائن | لا |
| `equity` | دائن | لا |
| `revenue` | دائن | لا |
| `expense` | مدين | نعم |

التصنيفات الفرعية المستخدمة في القوائم: `cash`, `bank`, `receivable`, `inventory`,
`fixed_asset`, `accumulated_depreciation`, `other_asset`, `payable`, `short_term_loan`,
`long_term_loan`, `capital`, `retained_earnings`, `drawings`, `sales`, `sales_return`,
`cost_of_sales`, `admin_expense`, `marketing_expense`, `finance_expense`,
`depreciation`, `other_revenue`, `other_expense`, `tax`.

## 2. القيد اليومي

القيد يتكوّن من سطور؛ لكل سطر حساب ومبلغ مدين أو دائن.

شروط الصحة:

```text
مجموع المدين = مجموع الدائن        (فرق أقل من 0.01 = متوازن)
كل سطر: مدين XOR دائن (لا الاثنان، ولا صفر)
تاريخ القيد داخل الفترة المالية المسموحة
الحساب موجود في دليل الحسابات
```

## 3. ميزان المراجعة

لكل حساب:

```text
رصيد مدين  = مجموع المدين − مجموع الدائن   (إن كان موجباً)
رصيد دائن  = مجموع الدائن − مجموع المدين   (إن كان موجباً)
صافي الرصيد = مدين − دائن
```

- **بالمجاميع**: إجمالي المدين وإجمالي الدائن لكل حساب.
- **بالأرصدة**: الرصيد الصافي وطبيعته.
- **افتتاحي**: القيود قبل تاريخ البداية.
- **ختامي**: الافتتاحي + حركة الفترة.
- التحقق: `إجمالي المدين = إجمالي الدائن`، وإلا تُعرض ملاحظة `TRIAL_BALANCE_DIFFERENCE`.

## 4. قائمة الدخل

```text
صافي المبيعات      = إيرادات المبيعات − مردودات المبيعات
تكلفة المبيعات     = مصروفات تصنيف cost_of_sales
مجمل الربح         = صافي المبيعات − تكلفة المبيعات
المصروفات التشغيلية = إدارية + تسويقية + إهلاك
الربح التشغيلي     = مجمل الربح − المصروفات التشغيلية
الربح قبل الضريبة  = الربح التشغيلي + إيرادات أخرى − مصروفات أخرى − مصروفات مالية
صافي الربح         = الربح قبل الضريبة − الضريبة (إن وُجدت)
```

تُبنى القائمة من حركة الفترة (لا من الأرصدة الافتتاحية) للحسابات ذات الطبيعة الدائنة
للإيرادات والمدينة للمصروفات.

## 5. قائمة المركز المالي

```text
الأصول المتداولة = نقدية + بنك + عملاء + مخزون + أصول متداولة أخرى
الأصول غير المتداولة = أصول ثابتة − مجمع الإهلاك + أصول أخرى
إجمالي الأصول = المتداولة + غير المتداولة

الالتزامات المتداولة = موردون + قروض قصيرة + مستحقات أخرى
الالتزامات طويلة الأجل = قروض طويلة + التزامات أخرى
حقوق الملكية = رأس المال + الأرباح المحتجزة + نتيجة الفترة − السحوبات − التوزيعات

التحقق: إجمالي الأصول = إجمالي الالتزامات + حقوق الملكية
```

عند اختلاف الطرفين تُعرض لافتة تحذير بالفرق وقيمته، ولا تُخفى القائمة.

## 6. التدفقات النقدية

تُبنى بالطريقة غير المباشرة من حركة حسابات النقدية والبنك:

```text
التشغيلي   = صافي الربح + الإهلاك ± التغير في رأس المال العامل
الاستثماري = التغير في الأصول الثابتة والأصول الأخرى
التمويلي   = التغير في القروض ورأس المال والسحوبات والتوزيعات
صافي التغير = التشغيلي + الاستثماري + التمويلي
نقدية آخر الفترة = نقدية أول الفترة + صافي التغير
```

إن غابت أرصدة افتتاحية كافية تُعلن القائمة "غير متاحة" بدل اختراع أرقام.

## 7. النسب المالية (المعادلات المعلنة في الواجهة)

| النسبة | المعادلة |
| --- | --- |
| نسبة التداول | الأصول المتداولة ÷ الالتزامات المتداولة |
| السيولة السريعة | (المتداولة − المخزون) ÷ الالتزامات المتداولة |
| هامش الربح الإجمالي | مجمل الربح ÷ صافي الإيرادات × 100 |
| هامش الربح التشغيلي | الربح التشغيلي ÷ صافي الإيرادات × 100 |
| هامش صافي الربح | صافي الربح ÷ صافي الإيرادات × 100 |
| المديونية | إجمالي الالتزامات ÷ إجمالي الأصول × 100 |
| حقوق الملكية | حقوق الملكية ÷ إجمالي الأصول × 100 |
| دوران المخزون | تكلفة المبيعات ÷ متوسط المخزون |
| أيام المخزون | 365 ÷ دوران المخزون |
| دوران العملاء | صافي الإيرادات ÷ متوسط العملاء |
| فترة التحصيل | 365 ÷ دوران العملاء |
| دوران الموردين | تكلفة المبيعات ÷ متوسط الموردين |
| فترة السداد | 365 ÷ دوران الموردين |
| العائد على الأصول | صافي الربح ÷ إجمالي الأصول × 100 |
| العائد على حقوق الملكية | صافي الربح ÷ حقوق الملكية × 100 |
| نسبة المصروفات | (تشغيلية + مالية) ÷ صافي الإيرادات × 100 |

**قاعدة:** إن كان المقام صفراً أو غاب الرصيد الافتتاحي اللازم (للدوران) تُعرض النسبة
"غير متاحة" مع سبب، ولا تُستبدل بقيمة تقديرية.

## 9. كشف التكرار (`duplicates.ts`)

يُحسب لكل مجموعة مرشحة مجموع نقاط من:

- تطابق رقم القيد/الفاتورة/السند،
- تطابق التاريخ (أو قربه)،
- تطابق المبلغ أو قربه،
- تطابق الطرف/الحساب،
- تشابه الوصف (معامل تشابه نصي).

النتيجة:

```text
≥ 80  → اشتباه قوي
≥ 55  → اشتباه متوسط
≥ 35  → اشتباه ضعيف
```

القيود المتكررة شهرياً بنفس المبلغ لا تُعد تكراراً بحد ذاتها (لا يوجد تطابق مرجعي)،
وكل النتائج **مؤشرات للمراجعة** ولا تُحذف تلقائياً.

## 10. قواعد المخاطر (`anomalies.ts`)

قيم افتراضية قابلة للتخصيص:

| القاعدة | القيمة |
| --- | --- |
| ارتفاع المصروف مقارنة بالمتوسط | ×1.8 وبحد أدنى 1000 |
| شذوذ إحصائي | أكثر من 3 انحرافات معيارية |
| مبلغ متكرر | 3 مرات على الأقل وبإجمالي ≥ 1000 |
| عتبة المستندات | 5000 |
| تركّز المصروف | ≥ 40% على حساب واحد |
| الحد الأدنى لأشهر التاريخ | 3 |
| الحد الأدنى للمبلغ | 100 |

كل نتيجة تحمل: السبب، درجة الثقة، البيانات المستخدمة، والتنبيه إلى أنها ليست دليل احتيال.

## 13. حدود معروفة (لا تُخفى على المستخدم)

1. **عملة واحدة**: المحرك لا يطبّق تحويل عملات. أي قيد بعملة مختلفة يُكشف بملاحظة `CURRENCY_MISMATCH` ولا تُصحّح قيمته تلقائياً.
2. **أرباح الفترات السابقة**: إذا لم تُقفل في «الأرباح المحتجزة»، يظهر فرق في المركز المالي ويُكشف بـ`BALANCE_SHEET_IMBALANCE`. النظام لا يُنشئ قيود إقفال تلقائياً.
3. **التدفقات النقدية**: تُعد بالطريقة غير المباشرة من تغيّر الأرصدة. عند وجود حركات نقدية غير مصنفة يظهر «فرق التسوية» ويُنبَّه المستخدم بدل إخفائه.
4. **نسب الدوران**: لا تُعرض إن غاب رصيد افتتاحي أو ختامي، بدل عرض رقم مضلل.
5. **لا واجهة لتعديل أو حذف القيود المرحّلة**: البيانات تُدخل بالاستيراد فقط، والتصحيح يتم باستيراد جديد.
