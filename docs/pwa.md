# PWA — تثبيت ركاز على الهاتف ونظام التحديث

المرحلة: **PWA فقط**. تحويل Android الأصلي (Capacitor/TWA) مرحلة مستقلة موثقة في
[`android-readiness.md`](./android-readiness.md).

## 1. ما تم بناؤه

| المكوّن | الملف | الوظيفة |
| --- | --- | --- |
| Web App Manifest | `src/app/manifest.ts` | هوية التطبيق، الأيقونات، الاختصارات، `display: standalone` |
| الأيقونات | `public/icons/*.png` · `src/app/icon.png` · `src/app/apple-icon.png` | 192/512/maskable/Apple — مولّدة من هوية ركاز |
| مولّد الأيقونات | `scripts/generate-pwa-icons.mjs` | إعادة التوليد: `npm run icons:pwa` |
| Service Worker | `public/sw.js` | تسجيل، تخزين أصول ثابتة، صفحة عدم اتصال، استقبال أوامر التحديث |
| سياسة الكاش | `src/lib/pwa/cache-policy.ts` | منطق خالص + اختبارات، ومطابقة لِـ `sw.js` |
| تسجيل SW + إشعار التحديث + شريط عدم الاتصال | `src/components/pwa/service-worker-provider.tsx` | يُركَّب في الـ layout الجذري |
| دعوة التثبيت | `src/components/pwa/install-prompt-banner.tsx` | تظهر فقط عند توفّر تثبيت آلي |
| زر التثبيت الدائم | `src/components/pwa/install-button.tsx` | صفحة الهبوط + الشريط الجانبي |
| سياسة العرض | `src/lib/pwa/install-policy.ts` | منطق خالص قابل للاختبار |
| صفحة عدم الاتصال | `src/app/offline/page.tsx` | تُخزَّن مسبقاً وتُعرض عند انقطاع الشبكة |
| الإصدار | `src/lib/pwa/version.ts` | `APP_VERSION` / `CACHE_VERSION` / تاريخ الإصدار |

## 2. Manifest

- `name`: «RAKAZ AI — ركاز | منصة الذكاء المحاسبي والمالي» · `short_name`: «ركاز»
- `lang: ar` · `dir: rtl` · `display: standalone` · `start_url: /dashboard` · `scope: /`
- `theme_color: #08352a` · `background_color: #f8fafc`
- أيقونات: 192×192، 512×512، و512×512 `purpose: maskable`
- اختصارات: لوحة التحكم، القوائم المالية، اكتشاف الأخطاء

`start_url` يشير إلى `/dashboard`، والـ proxy يحوّل الزائر غير المسجّل إلى `/login?next=/dashboard`
— فلا يفتح التطبيق على صفحة محمية بلا جلسة.

## 3. سياسة التخزين المؤقت

| نوع الطلب | الاستراتيجية |
| --- | --- |
| تنقّل (`mode: navigate`) | الشبكة فقط. عند الفشل تُعرض صفحة `/offline` المخزّنة مسبقاً |
| أصول ثابتة (`/_next/static/*`، `/icons/*`، خطوط، manifest) | Cache-first ثم الشبكة |
| `/api/*` | لا يُعترض إطلاقاً |
| طلبات غير `GET` | لا تُعترض |
| أي مسار محاسبي | لا يُعترض ولا يُخزَّن |

**لا يُخزَّن HTML لأي صفحة** — لا القوائم المالية، ولا دفتر الأستاذ، ولا التقارير، ولا الشركات.
ولا تُخزَّن أي استجابة تحمل `Set-Cookie`. وبهذا لا يمكن استخدام الكاش لتجاوز المصادقة أو RLS:
كل صفحة محاسبية تُطلب من الخادم في كل مرة، والخادم يتحقق من الجلسة والصلاحيات.

عند تسجيل الخروج يستدعي `app-shell` الرسالة `PURGE` فيحذف الـ SW كل الكاشات ثم يعيد تجهيز صفحة
عدم الاتصال فقط.

## 4. دعوة التثبيت — السياسة

| القاعدة | القيمة |
| --- | --- |
| المصدر | حدث `beforeinstallprompt` فقط |
| مهلة الظهور | 8 ثوانٍ بعد التحميل |
| التكرار في الجلسة | مرة واحدة (`sessionStorage`) |
| بعد «ليس الآن» | إخفاء 14 يوماً، ثم 45 يوماً، ثم توقف نهائي بعد 3 رفضات |
| عند التثبيت | لا تظهر أبداً (`appinstalled` + `localStorage`) |
| داخل standalone | لا تظهر |
| متصفح لا يدعم التثبيت الآلي | لا تظهر دعوة، ولا يظهر زر |

كل القيم في `INSTALL_POLICY` داخل `src/lib/pwa/install-policy.ts` — قابلة للتعديل في مكان واحد.

**زر التثبيت الدائم** يظهر في مكانين فقط: ترويسة صفحة الهبوط، وأسفل الشريط الجانبي. يظهر فقط
إذا كان التثبيت الآلي متاحاً (أو على iOS حيث يُعرض دليل «إضافة إلى الشاشة الرئيسية»)، ولا يظهر
إذا كان التطبيق مثبتاً أو يعمل داخل standalone.

## 5. نظام التحديث

1. الـ SW الجديد يُثبَّت لكنه **لا يتفعّل** (`skipWaiting` لا يُستدعى تلقائياً).
2. الواجهة تكتشف `registration.waiting` أو حدث `updatefound` ثم `installed`.
3. يُعرض إشعار «يتوفر إصدار جديد من ركاز» مع «تحديث الآن» و«تأجيل التحديث».
4. «تحديث الآن» يرسل `SKIP_WAITING`، ثم يُنتظر `controllerchange` ويُعاد التحميل **مرة واحدة**.
5. حارس ضد الحلقات: `sessionStorage["rakaz.sw.lastReloadAt"]` يمنع إعادة تحميل ثانية خلال 10 ثوانٍ.
6. «تأجيل التحديث» يُخفي الإشعار لهذه الجلسة فقط (`updateSnoozed`).
7. فحص دوري: كل 30 دقيقة وعند عودة التبويب للواجهة (`visibilitychange`).

الإشعار لا يظهر إذا لم يكن هناك عامل انتظار فعلي، ولا يُقال «تم التحديث» قبل `controllerchange`.

## 6. الإصدار

- `APP_VERSION` و`CACHE_VERSION` في `src/lib/pwa/version.ts` — يظهر `APP_VERSION` أسفل الشريط الجانبي.
- `CACHE_VERSION` في `public/sw.js` يجب أن يطابق `CACHE_VERSION` في TypeScript، ويوجد اختبار يفشل
  إذا اختلفا.
- **عند كل إصدار حقيقي:** ارفع `APP_VERSION` و`CACHE_VERSION` في الملفين. تغيير `sw.js` هو ما يجعل
  المتصفح يكتشف نسخة جديدة؛ تغيير الأيقونات أو الـ manifest وحده لا يكفي.
- لا يُستخدم تاريخ متغير ولا قيمة عشوائية.

## 7. عدم الاتصال

- شريط أحمر أعلى الصفحة عند `offline`: «لا يوجد اتصال بالإنترنت حالياً. لا يمكن تنفيذ العمليات
  المحاسبية حتى يعود الاتصال.»
- أي تنقّل أثناء الانقطاع يعرض `/offline` برسالة واضحة وزر «إعادة المحاولة».
- **لا يوجد Offline Accounting**: لا حفظ قيود ولا اعتماد ولا ترحيل دون اتصال. هذا قرار مقصود
  ويحتاج تصميمه واختباراته في مرحلة مستقلة.

## 8. التحقق اليدوي على Android

1. افتح `https://mizan-ai-accounting.vercel.app` في Chrome على Android.
2. انتظر ثوانٍ ثم اضغط زر التثبيت في الترويسة، أو القائمة ⋮ → «تثبيت التطبيق».
3. افتح التطبيق من الشاشة الرئيسية: يجب أن يفتح بلا شريط عنوان (standalone).
4. فعّل «وضع الطيران» ثم تنقّل: تظهر صفحة عدم الاتصال، ولا تظهر أي بيانات مالية قديمة.

> ملاحظة: التثبيت الآلي يتطلب HTTPS ودومين حقيقي (وليس localhost عبر شبكة) — يعمل على Vercel.
> لا يمكن اختبار نافذة التثبيت الحقيقية في متصفح آلي؛ الاختبارات تحاكي الحدث وتتحقق من المنطق.

## 9. القيود المعروفة

- لا توجد أيقونات مشروطة (monochrome) ولا `screenshots` في الـ manifest — تحسين اختياري لاحق.
- لا إشعارات Push ولا مزامنة خلفية — خارج نطاق هذه المرحلة.
- iOS لا يدعم `beforeinstallprompt`؛ يُعرض دليل يدوي فقط عبر زر التثبيت.
