# المساعد الذكي — الإعداد والتشغيل

المساعد في ركاز يعمل بطريقتين:

1. **محلياً دائماً**: إجابات محسوبة من محرك الحسابات، بلا أي اتصال خارجي (الوضع الافتراضي).
2. **عبر مزود AI**: عند ضبط مفتاح، تُصاغ الإجابة لغوياً من نفس الأرقام المحسوبة، ثم تُفحص قبل العرض.

## المتغيرات

| المتغير | إلزامي | الوصف |
| --- | --- | --- |
| `AI_PROVIDER_API_KEY` | نعم للتفعيل | مفتاح المزود. يُقرأ على الخادم فقط. |
| `AI_PROVIDER_BASE_URL` | لا | عنوان الـAPI المتوافق مع Chat Completions. الافتراضي `https://api.openai.com/v1`. |
| `AI_MODEL` | لا | اسم النموذج. الافتراضي `gpt-4.1-mini`. |
| `AI_MAX_TOKENS` | لا | حد طول الرد (800 افتراضياً). |
| `AI_TIMEOUT_MS` | لا | مهلة الطلب بالمللي ثانية (20000 افتراضياً). |

## مزودون مدعومون

أي مزود يقدّم `POST {base}/chat/completions` بنفس شكل OpenAI:

| المزود | `AI_PROVIDER_BASE_URL` | مثال `AI_MODEL` |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai/gpt-4.1-mini` |
| Groq | `https://api.groq.com/openai/v1` | `llama-3.3-70b-versatile` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Together | `https://api.together.xyz/v1` | `meta-llama/Llama-3.3-70B-Instruct-Turbo` |
| Ollama (محلي) | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |

> Azure OpenAI يحتاج ترويسة `api-key` ومسار `api-version` مختلفاً، ولا يعمل مباشرة بهذه الإعدادات.

## خطوات التفعيل

### محلياً

```bash
cp .env.example .env.local
# ضع المفتاح في .env.local
npm run ai:check      # يتحقق من الاتصال دون طباعة المفتاح
npm run dev
```

### على Vercel

Project Settings → Environment Variables → أضف `AI_PROVIDER_API_KEY` (و`AI_MODEL` إن أردت غير الافتراضي) ثم أعد النشر. لا تضف أي متغير ببادئة `NEXT_PUBLIC_` لأن ذلك يكشف المفتاح في المتصفح.

## ضمان عدم اختلاق الأرقام

كل طلب يمر بثلاث مراحل:

1. **بناء السياق على الخادم**: القوائم والنسب والملاحظات تُحسب بمحرك `Decimal`، وتُرسل كـJSON مع قيم منسقة.
2. **تعليمات صارمة**: استخدام الأرقام كما هي، ومنع الجمع أو الطرح أو حساب نسب جديدة.
3. **فحص ما بعد التوليد** (`src/lib/ai/grounding.ts`): كل رقم في إجابة النموذج يُقارن بقيم السياق؛ أي مبلغ ≥ 100 أو نسبة لا تطابق قيمة محسوبة يُرفض، وتُعرض الإجابة المحلية بدلاً منها مع سبب واضح للمستخدم.

السنوات (1900–2100) والأعداد الصغيرة (عدد الملاحظات مثلاً) مستثناة من الفحص لتقليل الإنذارات الكاذبة. الأرقام العربية والفواصل العربية مدعومة.

## السلوك عند الفشل

| الحالة | ما يراه المستخدم |
| --- | --- |
| لا يوجد مفتاح | إجابة محلية، وتنبيه في صفحة المساعد |
| مفتاح غير صالح (401/403) | إجابة محلية + «مفتاح مزود الذكاء الاصطناعي غير صالح أو منتهي» |
| تجاوز الحد (429) أو خطأ 5xx | إعادة محاولة واحدة ثم إجابة محلية + سبب |
| انتهاء المهلة | إجابة محلية + «انتهت مهلة الاتصال» |
| إجابة بأرقام غير محسوبة | إجابة محلية + «مُنع عرض إجابة تحتوي أرقاماً غير مستمدة…» |

لا تُسجَّل المفاتيح ولا تُعاد في أي استجابة. سجل العملية يحفظ الوضع (`ai` أو `local`) وطول السؤال فقط.

## التكلفة والخصوصية

- كل سؤال يرسل ملخصاً محسوباً لبيانات شركة واحدة فقط، وليس الملفات الخام.
- التكلفة تعتمد على المزود والنموذج؛ استخدم نموذجاً صغيراً للأسئلة المتكررة.
- في وضع Supabase تُقيَّد الطلبات بصلاحيات المستخدم على الشركة قبل بناء السياق.

## الاختبارات

```bash
npx vitest run src/tests/ai-provider.test.ts src/tests/ai-grounding.test.ts
```

اختبارات المزود تستخدم خادماً محلياً حقيقياً (HTTP) لا اعتراضاً وهمياً، وتغطي: نجاح الطلب، إعادة المحاولة عند 5xx، خطأ 401، استجابة غير صالحة، انتهاء المهلة، وغياب المفتاح.
